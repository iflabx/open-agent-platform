# Apache Tika

> 类型：多格式文件类型探测与老旧文档兼容抽取组件
>
> 采用定位：条件引入（老旧 / 生僻格式检测、元数据嗅探与前置路由辅助）
>
> 所属层：数据治理层
>
> 官方网站：https://tika.apache.org/
>
> 开源仓库地址：https://github.com/apache/tika

## 当前定位

`Apache Tika` 是本方案数据治理层中面向老旧格式与生僻文件类型的条件引入兼容组件，负责 MIME 类型探测、轻量级文件元数据嗅探、前置格式路由，以及对常规解析引擎未覆盖的历史二进制格式执行兜底文本提取。常规 PDF、Office 与复杂版面文档的默认结构化解析由 [Docling](/components/docling) 承担。

## 主要职责

- **文件类型探测与前置路由**：对入湖的多源非结构化文件进行 MIME 类型与编码识别，将标准文档分流至 `Docling`，将生僻或历史格式路由至兼容处理链路。
- **轻量级元数据嗅探**：在不触发重度版面解析的前提下快速提取文件作者、创建时间、格式属性等基础元数据。
- **老旧与生僻格式兜底提取**：兼容企业存量历史归档格式（如老旧 Office 二进制文件、邮件归档、压缩包及非主流文档格式）的基础文本抽取。
- **异常文件前置预检**：在文件进入深度解析前识别加密、损坏或不支持的文件类型，降低主解析链路异常率。

## 与其他组件关系

- **与 [Docling](/components/docling) 分工协作**：`Docling` 是默认非结构化文档结构化解析引擎，负责高保真版面与表格还原；`Apache Tika` 作为条件引入的前置嗅探与兼容辅助层，与 `Docling` 配合处理老旧或生僻文件。
- **与 [SeaweedFS](/components/seaweedfs)、[OpenMetadata](/components/openmetadata) 协同**：从 `SeaweedFS`（或企业既有 S3 兼容对象存储）读取待检文件对象，并将探测到的基础格式与文件元数据同步登记至 `OpenMetadata`。
- **与 [SeaTunnel](/components/seatunnel) 互补**：`SeaTunnel` 负责文件与对象数据采集同步，`Apache Tika` 负责采集后的格式探测、路由与兼容提取。
- **向下游供数边界**：仅将兜底提取的文本与基础元数据交付后续清洗与治理流程，不作为高精度 RAG 复杂版面文档的主解析来源。

## 适合场景

- 存在大量历史遗留二进制文档、邮件归档或生僻文件格式的企业存量文档库
- 需要在解析前统一执行文件类型（MIME）检测、元数据嗅探与分发路由的接入网关
- 对非主流格式执行低成本基础文本提取与异常预检

## 边界

- **不替代 [Docling](/components/docling)**：不承担 PDF、Office 等主流业务文档的默认 AI 版面分析、复杂表格结构还原与结构化 Markdown / JSON 输出。
- **不替代索引和检索引擎**：不承担向量化、全文索引或混合检索。
- **不替代复杂知识编排和 RAG 运行时**：不承担切片策略、上下文拼装与召回编排。

## 采用规则

- 本方案默认以 [Docling](/components/docling) 作为非结构化文档主解析引擎；`Apache Tika` 定位为**条件引入**的兼容与前置辅助组件，不作为最小起步组合的必选项。
- 当企业存量文档库包含大量老旧、生僻二进制格式，或需要在入库管道中建立统一的格式探测、元数据嗅探与路由分流层时按需启用 `Apache Tika`。
- 经 `Apache Tika` 兜底提取的纯文本仍须进入清洗、标签、目录、切片和索引链路，并明确标注解析来源，不可直接等同于版面结构化解析产物。

## 治理注意点

- **解析来源与质量分级标记**：需在元数据中区分 `Docling` 结构化解析产物与 `Apache Tika` 兜底抽取产物，便于下游检索与评测追溯质量差异。
- **异常与畸形文件防护**：对嵌套压缩包、加密文件、超大异常文件须设置解析超时与内存上限，防止解析进程资源耗尽。
- **权限与密级透传**：非结构化文档中的敏感信息和权限语义不得在嗅探或兜底提取过程中丢失。
- **元数据协同登记**：文件类型、来源路径、探测结果与异常状态应统一进入资产目录与审计记录。
