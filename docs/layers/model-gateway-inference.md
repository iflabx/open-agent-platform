# 7. 模型网关与推理层

> 定位：负责模型统一入口、模型路由、配额治理与推理执行。
>
> 当前承载组件：`LiteLLM`、`vLLM`、`Qwen` 模型族。

## 本层定义

模型网关与推理层是平台所有模型能力的标准供给面。

本层负责将对话、代码生成、Embedding、Reranker 与安全模型能力以统一协议接口供给上层，同时将模型路由、配额控制、失败回退与推理执行从业务代码中彻底剥离。

## 本层功能

- **统一模型调用入口**：对外提供标准化的模型调用协议与目录抽象。
- **路由与配额治理**：执行多模型路由、配额管控、限速与故障回退。
- **多模式推理执行**：承接低时延在线推理与高吞吐批量推理任务。
- **跨层模型供给**：为知识与检索层提供 Embedding / Reranker 能力，为编排层提供生成式推理能力。

## 边界

本层不承担以下职责：

- **业务界面与会话**：不承载业务会话管理与应用前台逻辑。
- **业务流程编排**：不替代 [Agent 编排层](/layers/agent-orchestration) 执行工作流编排。
- **数据与知识治理**：不直接处理源数据治理与知识资产发布。
- **业务级权限裁决**：不替代细粒度权限引擎执行业务级授权判断。

## 关键链路

### 1. 生成式推理链路

1. 编排层向统一模型入口发起调用请求。
2. `LiteLLM` 依据模型目录、路由策略与配额规则选择下游推理节点。
3. `vLLM` 执行模型推理并返回生成结果。
4. 观测层记录本次调用的 Token 成本、时延与质量指标。

### 2. 检索辅助链路

1. 知识与检索层发起 Embedding 或 Reranker 调用请求。
2. 模型层通过统一接口提供对应的向量化或重排能力。
3. 返回向量结果或重排分数，供知识层继续执行上下文组装。

## 治理要求

- **模型目录与用途收敛**：清晰划分模型目录、适用场景与配额上限，严禁业务应用随意硬编码模型地址。
- **能力边界清晰**：明确区分安全审核模型、Embedding / Reranker 模型与主生成模型的用途边界。
- **调用归因可追踪**：观测数据须能准确归因至具体应用、用户、模型名称与版本策略。
- **变更门禁保护**：模型版本升级须配合回归评估与发布门槛，严禁直接在生产流量上全量切换。

## 部署与发布要求

- **网关与推理分离**：模型网关与推理执行引擎建议分层部署，避免控制面与计算面职责混杂。
- **算力资源分池**：GPU 算力应区分在线交互请求与离线批量任务，分别进行容量规划。
- **灰度与容量预估**：模型发布需支持灰度切流、快速回退与并发容量预估。
- **协议接口解耦**：保持对外调用协议统一，避免上层应用强依赖特定推理后端实现细节。

## 风险与取舍

- **应用直连导致治理失控**：若各业务应用自行选型并直连底层推理服务，成本、配额与安全治理将无法收敛。
- **模型目录无序膨胀**：模型覆盖范围越广，越需清晰界定默认模型与条件模型的采用边界。
- **黑盒入口降低排障效率**：将检索模型、生成模型与安全模型混为单一黑盒入口，将显著增加故障定位难度。
