# JSON Schema

> 类型：数据结构与参数约束标准
>
> 采用定位：跨层通用数据结构与参数校验标准
>
> 当前口径：截至 2026-03-16，`JSON Schema` 官方规范页当前发布版本仍为 `Draft 2020-12`

## 定位与价值

`JSON Schema` 是本方案中用于描述 JSON 结构、约束参数、校验输入输出与表达结构化结果的统一数据结构标准。

它并非单个组件的私有能力，而是跨门户、工具、模型输出、配置与数据契约复用的通用约束语言。

## 标准约束什么

- **请求与响应结构**：约束 JSON 请求体、响应体与结构化结果的字段形态。
- **参数与配置规则**：约束工具参数、函数参数与受控配置的字段定义。
- **类型与引用关系**：规范字段类型、必填项、枚举值、组合关系与复用引用。
- **可编程消费契约**：保障模型结构化输出与工具调用输入能够被程序稳定解析。

## 核心内容

- **基础校验关键字**：`type`、`properties`、`required`、`enum` 等基础字段约束。
- **数组结构表达**：`items`、`prefixItems` 等数组元素约束能力。
- **组合约束逻辑**：`allOf`、`anyOf`、`oneOf`、`not` 等复合条件校验。
- **方言与复用机制**：`$schema`、`$ref`、`$defs` 等方言声明、定义与引用机制。
- **Draft 2020-12 演进**：涵盖数组语义、动态引用与 vocabulary 组织方式的规范更新。

## 在方案中的落点

- **工具与结构化输出**：作为工具调用参数与模型结构化结果的统一描述方式。
- **模型接口协同**：在模型服务接口中，与 [OpenAI 兼容 API](/standards/openai-compatible-api) 配合约束结构化输出。
- **门户与接口校验**：在门户 / BFF / API 层中，作为 JSON 请求与配置对象的统一校验口径。
- **互操作契约底座**：在协议与互操作场景中，为工具参数与受控输入输出提供可复用结构描述。

## 与组件 / 协议关系

- **与 [OpenAI 兼容 API](/standards/openai-compatible-api) 紧密配合**：集中体现在结构化输出与工具参数定义场景。
- **与 [LiteLLM](/components/litellm)、[vLLM](/components/vllm) 协同**：属于“标准约束”与“接口实现”的配合关系。
- **与 [OpenAPI](/protocols/openapi) 互补**：`OpenAPI` 侧重接口契约描述，`JSON Schema` 侧重数据结构约束。
- **与 [MCP 协议](/protocols/mcp) 配合**：为工具协议提供输入输出结构校验能力，但不替代协议本身。

## 适用场景

- 工具参数定义与校验
- 模型结构化输出
- 门户 / API 输入输出约束
- 受控配置与数据契约定义

## 边界

- 不替代传输协议或接口协议。
- 不替代权限策略语言与审批规则。
- 不等同于 UI 标准或表单渲染规范。
- 用于模型结构化输出时，不同推理实现通常仅支持其子集，不能假定完整特性均可直接使用。

## 采用规则

- **统一基线版本**：统一以 `Draft 2020-12` 作为公开基线，不混用多套 Draft 口径。
- **显式声明方言**：所有正式结构定义应显式声明 `$schema`，避免隐式方言漂移。
- **限定模型输出子集**：面向模型结构化输出时，优先使用当前接口与模型实现稳定支持的 Schema 子集。
- **契约资产版本化**：将结构定义作为可版本化资产纳入治理，避免以匿名对象形式散落在应用代码中。

## 治理注意点

- **分级管理契约变更**：明确 Schema 变更的兼容性策略，区分向后兼容与破坏性变更。
- **锁定校验器口径**：生产链路中的校验器与生成器应固定至可验证的 Draft 口径。
- **明确资产归口**：为工具参数、模型输出与配置结构指定统一归口与责任人。
- **端到端实测验证**：对模型结构化输出，必须在真实模型与真实接口上验证遵循稳定性，避免定义合法但模型输出失稳。
