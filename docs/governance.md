# 安全与治理

::: info 核心摘要
本页定义企业级智能体平台的**安全控制基线、动作治理机制与发布准入门槛**，与 [方案](/framework)、[总体架构](/architecture)、[协议与标准体系](/protocol-standards) 保持一致。

- **身份与授权分层**：优先复用企业现有 `SSO / IAM`，由 `APISIX` 负责北向入口认证接入，`Casbin` 负责应用内与动作级细粒度裁决。
- **高风险动作兜底**：涉及写入、外发、权限变更或生产操作的高风险动作，强制引入人工确认与 `Maker-Checker` 复核节点。
- **双层观测与发布门槛**：结合平台级（`OpenTelemetry` 栈）与 AI 级（`LangFuse`）双层可观测性（Observability），按需引入 `LangSet` 承接可追溯的版本化评测数据集工程与离线回归评测，并以 `k6` 压测作为上线容量门槛。
:::

## 治理目标

结合 NIST AI RMF 的风险治理框架，企业级智能体平台至少须同时达成以下六项治理目标：

1. **最小权限访问**：确保正确的主体仅能在授权上下文中访问对应数据与工具。
2. **全链路变更可控**：模型、知识、Prompt、工具与安全策略变更均须可追踪、可回放、可回滚。
3. **策略硬约束优先**：平台输出与自动化动作始终受确定性策略约束，不完全依赖模型临场判断。
4. **高风险人工兜底**：高风险任务具备显式人工确认、人工接管与事后复盘机制。
5. **发布前量化验证**：质量、时延、成本与容量门槛在上线前完成验证，而非线上事后补救。
6. **治理内建可扩展**：治理能力从试点阶段即内建于平台底座，随业务规模扩大平滑演进。

## 治理域总览

| 治理域 | 重点问题 | 主控能力 | 结果要求 |
| --- | --- | --- | --- |
| 身份与组织 | 谁能进入系统、主体身份、所属租户与部门 | 企业现有 `SSO / IAM`、`APISIX` | 入口身份可信、组织属性可传递 |
| 授权与动作控制 | 谁能看、谁能调、谁能执行高风险动作 | `Casbin`、应用内审批与 `Maker-Checker` 规范 | 最小权限、动作可裁决 |
| 数据与知识安全 | 哪些数据可入库、可检索、可进入 Prompt | 数据治理链路、权限标签、检索过滤 | 严禁越权数据进入模型上下文 |
| 模型与 Prompt 治理 | 使用何种模型、何时切换、何时允许升级 | `LiteLLM`、Prompt 版本化、离线评测门槛（按需引入 `LangSet`） | 模型与配置可控、可审计 |
| 观测与审计 | 发生了什么、原因是什么、能否复盘 | `LangFuse`、`OpenTelemetry`、`Prometheus`、`Grafana`、`Loki` | 关键链路留痕完整 |
| 发布与运行治理 | 变更何时可上线、异常如何回滚 | 离线回归评测（`LangSet` 条件引入）、在线评测与回放（`LangFuse`）、灰度、`k6` 基线、发布流程 | 有准入门槛，有回滚路径 |

## 核心组件承载关系

| 治理能力 | 主控组件 | 职责说明 |
| --- | --- | --- |
| 北向认证接入与流量治理 | `APISIX` + 企业现有 `SSO / IAM` | 负责入口身份接入、路由、限流和审计前置 |
| 细粒度授权 | `Casbin` | 负责应用内动作级裁决和策略执行 |
| 知识权限过滤 | `OpenMetadata` + `LlamaIndex` | 负责标签治理、可见范围和检索前过滤 |
| 模型调用治理 | `LiteLLM` | 负责模型路由、配额、留痕和切换控制 |
| LLM 观测与评测 | `LangFuse` | 负责在线 Prompt 观测、Trace、评分沉淀和样本回放 |
| 评测数据集工程与离线回归 | `LangSet`（条件引入） | 负责可追溯的版本化评测数据集准备、不可变版本血缘与离线回归评测触发，与 `LangFuse`、`k6` 互补 |
| 平台级观测 | `OpenTelemetry` + `Prometheus` + `Grafana` + `Loki` | 负责指标、日志和全链路追踪 |
| 发布前容量门槛 | `k6` | 负责入口、编排、检索和模型链路压测 |

## 身份与权限

### 统一身份主链路

身份认证与授权裁决沿以下主链路贯通：

企业现有 `SSO / IAM` → `APISIX` → 门户 / BFF → `Casbin` → 知识服务 / 工具服务 / 业务服务

各节点职责严格分离：

- **企业现有 `SSO / IAM`**：负责身份源管理、统一登录、组织架构与账号生命周期。
- **`APISIX`**：负责北向入口认证接入、流量治理、审计前置与安全策略前移。
- **`Casbin`**：负责应用内与动作级的细粒度授权裁决。
- **业务应用与 Agent Runtime**：仅消费上游透传的身份与授权上下文，禁止自行重复建设独立权限体系。

若企业尚未建立统一 IAM，应优先补齐兼容 `OIDC / OAuth2 / SCIM` 的身份基础设施，但不改变优先复用企业现有身份体系的架构基线。

### 授权模型

企业级平台至少组合使用三类授权机制：

- **`RBAC`**：处理岗位、角色、应用菜单与常规功能授权。
- **`ABAC`**：处理部门、租户、项目、数据安全等级、地域与流程阶段等属性上下文限制。
- **工具级授权**：处理业务写操作、外部通知、审批提交与数据库执行等高风险动作权限。

### 组织与身份上下文透传

身份上下文进入智能体平台后，至少须保留并沿门户、编排、检索、工具与审计全链路传递以下字段（不得仅在登录页生效）：

- 用户 ID
- 部门 / 组织
- 角色
- 租户
- 会话来源渠道
- 应用或场景 ID
- 临时授权或审批状态

## 数据与知识安全

### 入库前控制

任何面向 AI 的知识资产入库前，必须依次经过以下治理环节：

- 数据分类分级
- 敏感信息识别与脱敏
- 所属部门、业务域与责任人标注
- 生命周期状态与可见范围定义
- 非结构化内容解析与格式清洗

### 检索时控制

检索环节不能仅关注召回率，还须同步执行四项安全与质量控制：

- 基于角色、租户、部门与安全标签的检索前权限过滤
- 对命中来源与引用片段进行可追溯记录
- 对过期、失效与冲突数据实施抑制或过滤
- 对注入模型的上下文拼装范围实施最小化控制

### Prompt 与输出控制

Prompt 组装与模型输出至少须满足以下约束：

- 严禁将未经授权的数据内容注入模型上下文。
- 对高风险话题与高风险动作实施前置规则拦截。
- 输出结果保留来源引用或行动依据。
- 命中高风险条件时自动触发人工确认或二次校验。

## 模型、Prompt 与路由治理

### 模型治理

模型选用不得临时随意替换，必须受控于统一路由与准入白名单：

- 统一经 `LiteLLM` 向上层暴露模型调用入口。
- 按业务场景等级维护白名单模型池。
- 以时延、成本、准确率与安全策略命中率作为模型切换评估依据。
- 模型切换必须经过离线评测与小流量灰度验证，禁止直接在生产环境全量生效。

### Prompt 与配置治理

凡会影响智能体运行行为的配置，均须作为正式发布项纳入版本管理与变更审计：

- Prompt 模板
- 工具描述与参数 Schema 模板
- 知识源绑定关系
- 检索与重排参数
- 模型路由策略
- 安全规则与判定阈值

## 工具与动作治理

一旦智能体进入具备执行外部动作能力的阶段，治理重点即从内容准确性升级为动作可控性。

### 工具风险分级

工具能力至少划分为三个风险等级：

- **只读查询**：如知识检索、状态查询、指标查询。
- **低风险写入**：如生成内容草稿、创建待审核记录。
- **高风险动作**：如发送外部通知、执行 SQL、提交审批、变更业务系统数据。

### 高风险动作强制要求

所有高风险动作必须同时满足以下四项要求：

1. **前置权限裁决**：执行前完成 `Casbin` 动作级权限校验。
2. **显式人工确认**：动作执行前或关键节点中引入人工确认或 `Maker-Checker` 复核。
3. **结果与补偿记录**：动作执行后完整记录返回结果、失败原因与补偿动作。
4. **端到端责任可追**：审计日志须完整关联“谁授权、谁执行、执行了何种操作”。

## 审计与可观测性（Observability）

### 审计字段基线

| 维度 | 必须记录的关键字段 |
| --- | --- |
| 用户访问 | 用户 ID、租户、角色、入口渠道、应用 ID、会话 ID |
| 检索过程 | 数据源、命中记录、权限过滤结果、引用 ID、重排结果 |
| 模型调用 | 模型名称、路由策略、输入摘要、输出摘要、Token 成本、时延 |
| 工具执行 | 工具名称、参数摘要、执行结果、失败原因、补偿动作 |
| 安全策略 | 命中规则、审查结论、人工接管标记、审批记录 |
| 发布变更 | 变更对象、变更人、评测结论、灰度批次、回滚记录 |

### 双层观测体系

平台可观测性（Observability）划分为两个互补层级，缺一不可：

- **平台级观测**：由 `OpenTelemetry` + `Prometheus` + `Grafana` + `Loki` 承担系统运行面的指标、日志与全链路追踪。
- **AI 级观测**：由 `LangFuse` 承担 LLM 行为面的 Prompt 版本、调用 Trace、离线评测与样本回放。

## 发布门槛

### 上线前标准准入流程

任何影响平台运行行为的变更，上线前至少须依次通过以下七个环节：

1. 变更登记与责任人确认
2. 离线评测或回归样本集验证（需要协同维护可追溯、版本化黄金测试集与持续离线回归评测时，可条件引入 `LangSet`，并与 `LangFuse` 在线观测评分联动）
3. 安全规则与权限策略校验
4. `k6` 基线压测与关键链路容量验证
5. `staging` 环境集成验证
6. 小流量灰度发布
7. 正式发布与线上审计抽样复盘

### 核心观测与验收指标

- 问答正确率与来源引用有效率
- 工具调用成功率
- 高风险动作误触发率
- P95 时延与请求失败率
- Token 消耗成本与单位请求成本
- 安全规则命中率与人工接管率

## 人机协同与人工接管

::: warning 自动化动作红线
凡涉及审批、资金、合同、客户外发、生产系统写入与数据库改写等高风险环节，严禁将模型输出建议直接等同于系统最终执行动作。
:::

人机协同机制须满足以下架构要求：

- **显式确认节点**：将人工确认设计为流程中的显式状态节点，而非异常发生后的事后补救。
- **可中断可接管**：对高风险长链路流程保留暂停、撤回、重试与人工接管能力。
- **评测与审计闭环**：将人工介入记录与修正结果回流至审计日志与离线评测样本集。

## 治理角色分工

| 角色 | 主要责任 |
| --- | --- |
| 平台团队 | 维护平台底座、观测、发布流程和跨场景能力 |
| 业务负责人 | 定义业务目标、验收指标、人工接管规则 |
| 数据负责人 | 确认数据源范围、分类分级、知识可见范围 |
| 安全 / 合规团队 | 审核身份接入、权限模型、审计与高风险动作策略 |
| 运维团队 | 维护环境、容量、备份、恢复和故障处理 |
