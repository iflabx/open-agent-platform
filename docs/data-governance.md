# 数据治理层（企业 AI 数据底座）

::: info 核心摘要
数据治理层位于企业原始业务系统与 AI 消费层之间，负责将结构化、非结构化与半结构化数据转化为**可治理、可授权、可复用、可追溯**的 AI 可消费数据服务。

- **治理前置**：数据须先经登记、分层清洗、元数据建档与权限打标，再进入知识索引与 Agent 消费。
- **统一底座**：核心组合收敛为 `OpenMetadata`、`SeaTunnel`、`dbt Core`、`Docling`（`Apache Tika` 作为老旧 / 偏门格式与元数据预路由条件兼容项）、`MinIO`、`PostgreSQL`、`LlamaIndex` 与 `Weaviate`（`Milvus` 与 `Elasticsearch` 按条件演进兼容）。
- **关联阅读**：[总体架构](/architecture) · [技术选型](/stack) · [组件](/components) · [安全与治理](/governance) · [企业智能体能力与规范体系](/capability-framework)
:::

## 设立独立数据治理层的必要性

企业 AI 平台最常见的架构失败模式，是由各业务应用直接从源系统临时取数，再各自完成文档切片、权限校验与向量索引。这种模式会引发四类系统性问题：

- **数据质量失控**：数据源分散且缺乏清洗规范，导致知识供给不稳定。
- **权限口径割裂**：不同应用各自维护权限过滤规则，存在越权泄露风险。
- **多模态数据割裂**：结构化数据与非结构化文档各自为政，难以协同消费。
- **资产无法复用**：每个 AI 应用重复建设同步与解析链路，运维成本成倍增长。

因此，企业级智能体平台必须在源系统与 AI 消费层之间设立独立的数据治理层。

## 架构定位

数据治理层的核心供给链路如下：

源系统 → 数据治理层 → AI 可消费数据服务 → RAG / 搜索 / 查询 / Agent

该层的核心职责并非简单执行数据副本存储，而是将企业原始数据持续转化为受控、可复用的 AI 数据资产。

## 治理范围

### 1. 结构化数据

- ERP、CRM、HR、财务、供应链等核心业务系统
- 工单、订单、客户、产品、组织、项目等业务对象
- 数据仓库、湖仓一体平台与报表系统

### 2. 非结构化数据

- PDF、Word、Excel、PPT 等办公文档
- Wiki、制度规范、产品说明、FAQ
- 邮件、会议纪要、表单附件
- 接口文档、运维手册、项目交付资料

### 3. 半结构化内容

- JSON、CSV、XML 等结构化交换文件
- OCR 识别后的文本内容
- 表格抽取结果与附件元数据

## 端到端数据治理链路

### 1. 数据源登记

所有数据源必须遵循“先登记、后接入”的治理规范。

最低登记字段：

- 数据源名称
- 系统 owner
- 数据责任人
- 接入方式
- 更新频率
- 数据分类分级
- 允许消费的 AI 场景范围

治理目的：明确数据来源边界、责任归属与合规使用范围。

### 2. 数据采集与进入原始层

数据采集不等于直接构建向量索引，所有源数据须先接入统一治理链路。

典型接入方式：

- 批量同步
- 增量同步
- CDC（变更数据捕获）
- API 拉取
- 文件导入接入

治理要求：

- 采集过程全程可追踪
- 采集失败支持自动重试
- 同步频率按业务 SLA 可配置
- 不同源系统遵循统一接入契约

方案落点：`SeaTunnel`、`MinIO`。

### 3. 分层存放与标准化

数据底座至少划分为三个逻辑层级：

- **Raw（原始层）**：保留未经改动的原始数据与原始文件。
- **Staged（治理中间层）**：存放经解析、清洗与标准化转换的中间结果。
- **Curated（可消费层）**：存放完成治理、可直接面向 AI 发布的受控数据资产。

分层治理的核心价值在于支持全链路回溯、索引重建、治理前后差异比对，以及合规审计与质量追踪。

方案落点：原始文件与对象数据由 `MinIO` 承接；治理中间结果与元数据配置由 `PostgreSQL` 承接。

### 4. 解析、清洗与结构化处理

数据进入治理层后，须先完成可消费化预处理：

- 非结构化文档内容解析
- 文本抽取与格式清洗
- 重复内容去重与噪声过滤
- 结构化字段标准化
- 业务实体与分类标签对齐

方案落点：`Docling` 负责非结构化文档默认高保真解析（版面理解与表格还原），`Apache Tika` 保留为老旧 / 偏门格式兼容抽取与轻量元数据预路由条件项；`dbt Core` 负责结构化数据标准化与建模。

### 5. 元数据、血缘与责任归属

企业 AI 数据底座必须建立统一元数据目录，确保下游知识检索与模型回答具备可解释的来源依据。

最低元数据治理项：

- 数据来源
- 更新时间
- 数据 owner
- 责任部门
- 权限标签
- 生命周期状态
- 上下游血缘关系

方案落点：`OpenMetadata`、`PostgreSQL`。

### 6. 权限标签与分类分级

AI 平台不得仅在检索阶段临时判断权限，权限标签须在数据治理阶段即固化为数据资产的固有属性。

最低要求：

- 数据分类分级标识
- 部门 / 项目 / 租户归属标签
- 敏感字段标记
- 生命周期状态与可见范围定义

落地要求：

- 权限标签须同步写入下游索引元数据。
- 权限标签须能被检索层与结构化查询链路直接消费。
- 不同 AI 应用复用同一套经治理的可见范围策略。

### 7. 知识与索引发布

数据治理层的终点不是完成存储，而是将治理后的资产发布为标准化 AI 可消费服务，覆盖四类供给形态：

1. RAG 数据服务
2. 搜索数据服务
3. 结构化查询数据服务
4. Agent 上下文数据服务

方案落点：

- **知识工程与索引编排**：`LlamaIndex`
- **默认向量检索底座**：`Weaviate`
- **大规模条件演进**：当数据规模与多租户隔离要求显著上升时，条件演进至 `Milvus`
- **全文 / 混合检索兼容**：按需兼容 `Elasticsearch`

### 8. 生命周期与失效治理

数据治理层须覆盖数据资产的完整生命周期，至少包括：

- 新增
- 更新
- 失效
- 归档
- 重建索引
- 下线

::: warning 生命周期治理红线
若缺少端到端生命周期联动机制，将直接引发三类高危隐患：原始文档删除后向量索引仍残留、权限收紧后旧索引继续越权可见、已失效制度内容继续被模型引用作答。
:::

## 面向 AI 系统的四类供给方式

### 1. 面向知识问答与 RAG

- 提供经清洗切分的治理文档片段
- 提供完整来源元数据
- 提供 ACL 权限标签
- 提供检索、重排与来源引用所需字段

### 2. 面向企业搜索

- 提供全文检索索引
- 提供关键词、标签与结构化过滤条件
- 提供混合检索所需的向量与元数据字段

### 3. 面向查询型 Agent

- 提供受控结构化查询视图
- 提供标准化指标口径与字段业务释义
- 提供可审计的统一查询入口

### 4. 面向多 Agent 与业务应用

- 提供统一业务实体与主数据视图
- 提供跨系统标准化上下文
- 提供可信来源引用链

## 核心模块拆分

| 模块 | 主要职责 | 方案落点 |
| --- | --- | --- |
| Source Registry | 数据源登记、owner、分级、接入配置 | `OpenMetadata` |
| Ingestion Service | 批量、增量、CDC、API、文件采集 | `SeaTunnel` |
| Processing Pipeline | 文档解析、清洗、标准化、建模 | `Docling`（默认）、`Apache Tika`（条件兼容）、`dbt Core` |
| Metadata Catalog | 元数据、标签、血缘、责任人 | `OpenMetadata` |
| Policy Tagging | ACL、数据域、敏感级别、生命周期标签 | 数据治理流程 + 元数据体系 |
| Indexing Service | 向量索引、检索编排、引用构建 | `LlamaIndex` + `Weaviate` |
| Data Product Service | RAG、搜索、查询、Agent 上下文服务发布 | 门户 / BFF / 编排层消费 |

## 核心组件组合

为同时满足 RAG / 搜索 / 查询 / Agent 四类数据供给需求并保持技术栈收敛，数据治理与检索链路的核心组件组合如下：

- `OpenMetadata`
- `SeaTunnel`
- `dbt Core`
- `Docling`
- `MinIO`
- `PostgreSQL`
- `LlamaIndex`
- `Weaviate`

条件演进与兼容边界：

- **`Apache Tika`**：保留为条件兼容项，用于老旧 / 偏门文件格式兼容抽取与轻量元数据预路由。
- **`Milvus`**：数据规模、多租户隔离或检索性能要求显著上升后的条件演进底座。
- **`Elasticsearch`**：全文与混合检索场景的兼容项，不作为默认长期并行底座。

::: tip 数据治理核心原则
数据治理层须确保四项底线落到实处：企业数据先治理后供 AI 消费；多套 AI 应用复用同一套治理资产；权限、标签、版本与生命周期贯穿索引和查询层；AI 应用消费受控数据服务，严禁直连原始业务系统。
:::
