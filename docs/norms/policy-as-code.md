# Policy as Code

> 类型：策略治理规范
>
> 采用定位：策略资产化与受控发布治理基线
>
> 当前口径：截至 2026-03-17，`Policy as Code` 仍然更适合被定义为一类治理与工程实践，而不是单一正式标准；当前公开权威口径可参考 CNCF 对 `Policy as Code` 的定义，以及 Open Policy Agent 官方文档对策略语言、Bundle 分发和 Decision Logs 的工程实践
>
> 权威来源：CNCF Glossary、OPA 官方文档；本方案不引入新策略组件，规范主要约束既有 `Casbin` 策略、网关规则、模型与工具治理配置的受控管理方式
>
> 执行落点：`Casbin` 策略资产、门户 / BFF 规则配置、网关与运行时受控策略、发布流程与审计链路

## 定位与价值

`Policy as Code` 是本方案的策略资产化治理基线。

它要求将权限、审查、风险控制、工具可用范围、模型路由规则与关键阈值等“会改变系统行为的策略项”，从零散代码与人工口头配置中剥离出来，转化为可版本化、可评审、可测试、可发布、可回滚的受控资产。

## 规范约束什么

- **策略资产界定**：明确哪些规则必须归类为策略资产，禁止隐藏在业务代码或环境变量中。
- **全生命周期治理**：规范策略的编写、评审、测试、发布、审计与回滚流程。
- **分发与裁决留痕**：规范策略如何分发至各执行点，并在运行时输出可追踪的裁决记录。
- **异常兜底机制**：明确策略执行失败、依赖不可用或上下文缺失时的安全降级策略。

## 核心原则

- **策略与代码解耦**：避免业务逻辑与治理规则耦合为不可审查的黑盒。
- **受控变更发布**：策略变更须经版本管理、评审与发布流程，禁止直接在线热修改。
- **发布前可验证**：关键策略上线前须具备静态校验、单元测试与兼容性检查能力。
- **决策全程可追踪**：运行时裁决须记录命中规则、输入上下文与裁决结果。
- **失败默认收敛**：策略执行异常时须有明确的失败模式与默认保守行为，严禁默认放行。

## 在方案中的落点

- **权限模型资产化**：[Casbin](/components/casbin) 的模型与策略规则作为正式策略资产纳入版本管理与发布流程。
- **规则配置收敛**：门户 / `BFF` / 工具层的高风险动作限制、工具白名单、环境开关与租户规则，不得散落在临时代码分支中。
- **平台运行治理**：模型路由、知识可见范围、Prompt 安全阈值与外部动作限制均按策略资产而非实现细节管理。
- **灰度与回滚保障**：发布流程须支持策略测试、灰度验证、一键回滚与变更审计，防止单条规则误改引发全平台行为漂移。

## 与组件 / 协议关系

- **与 [Casbin](/components/casbin) 的关系**：属于“策略治理规范”与“策略裁决实现”的关系。
- **与 [OpenAPI](/protocols/openapi) 区分**：接口契约描述接口形态，策略资产定义接口在何种条件下可被调用。
- **与 [OpenTelemetry](/standards/opentelemetry) 及审计链路配合**：记录策略命中与决策结果，形成可复盘证据链。
- **与 [Maker-Checker](/norms/maker-checker) 配合**：高风险策略变更本身也应纳入审批与双人复核流程。

## 适用场景

- 授权与访问控制策略
- 工具白名单、黑名单与动作分级
- 数据访问、知识检索与租户隔离规则
- 模型路由、成本阈值、风险阈值与发布门槛
- 网关与平台运行时的统一策略收敛

## 边界

- 不等同于引入某个特定开源项目；它首先是一种工程治理方法。
- 不替代业务规则设计与责任归属，代码化本身不保证策略逻辑正确。
- 不替代审批流；高风险策略上线仍须经过人工评审与受控发布。
- 不要求所有配置都采用复杂 DSL，核心在于是否纳入受控生命周期管理。

## 落地规则

- **明确策略资产清单**：至少涵盖授权规则、工具限制、风险阈值、模型路由与关键安全开关。
- **全量入库与责任绑定**：所有正式策略资产均须进入版本库，明确责任人、评审人、变更说明与回滚路径。
- **发布前自动化门禁**：策略发布前至少通过静态校验、示例测试与关键场景回归验证。
- **运行时决策日志**：运行时须记录策略版本、输入上下文摘要、命中规则与裁决结果。
- **高风险保守兜底**：策略执行异常且涉及高风险动作时，默认收敛至保守拒绝路径，严禁默认放行。

## 治理注意点

- **防止规则过度叠加**：避免将环境差异、租户例外与历史兼容逻辑持续堆叠在同一套策略中导致规则失控。
- **分层划分策略边界**：明确区分“平台级通用策略”与“业务场景特定策略”，避免职责边界模糊。
- **建立变更分级门槛**：对权限、数据、外发动作与模型切换等高敏规则设置更严格的审批与发布门槛。
- **打通全链路闭环审计**：确保策略日志与审计日志能够关联至具体请求、用户、应用与发布批次。
