# RBAC + ABAC

> 类型：授权模型规范
>
> 采用定位：平台统一授权模型基线
>
> 当前口径：截至 2026-03-17，`RBAC` 的稳定公共基线仍可追溯到 NIST RBAC 模型与 ANSI/INCITS 359；`ABAC` 的权威公开基线采用 NIST SP 800-162（2019 更新版）。在企业智能体平台中，两者应组合使用，而不是二选一
>
> 权威来源：NIST RBAC 项目资料、NIST SP 800-162、NIST 术语表中的 `least privilege` 与 `separation of duty`
>
> 执行落点：企业现有 `SSO / IAM` 负责身份来源，`Casbin` 负责授权裁决，门户 / BFF / 知识服务 / 工具服务负责执行点落地

## 定位与价值

`RBAC + ABAC` 是本方案的统一授权模型基线。

其目标不仅在于控制“登录后能否进入系统”，更在于将“谁能访问哪个应用、检索哪些知识、调用哪些工具、在何种上下文中执行哪些动作”统一收敛为可裁决、可审计、可回滚的授权规则体系。

## 规范约束什么

- **静态访问范围**：约束用户、服务账号与系统主体可访问的应用、菜单、接口与能力范围。
- **动态上下文校验**：校验在租户、部门、项目、数据等级、地域与时间窗等上下文下，访问权限是否依然成立。
- **高风险附加约束**：约束高风险工具调用、写操作与审批动作所需满足的额外条件。
- **合规基线检查**：校验权限变更、临时授权与角色组合是否违背最小权限或职责分离原则。

## 核心原则

- **稳定权限面由 `RBAC` 承接**：覆盖岗位、角色、应用入口、常规功能与基础操作。
- **动态约束面由 `ABAC` 承接**：覆盖部门、租户、项目、数据标签、环境、流程阶段与风险等级。
- **高风险动作多维判定**：高风险操作不得仅依赖角色判定，必须叠加属性、上下文或审批状态。
- **认证与授权分离**：身份来源于企业既有 `IAM / SSO`，授权裁决由平台统一执行。
- **最小权限与职责分离**：默认遵循最小权限原则，并对关键岗位组合执行职责分离约束。

## 在方案中的落点

- **门户与应用层**：采用 `RBAC` 管理应用入口、工作台菜单、管理台功能与基础操作权限。
- **知识检索与数据访问**：采用 `ABAC` 叠加部门、租户、数据域、密级与标签过滤。
- **工具调用与外部动作**：采用“角色 + 属性 + 动作分级”的组合裁决，严禁仅依赖前端隐藏按钮实现控制。
- **高风险流程联动**：在授权判定之外与 [Maker-Checker](/norms/maker-checker) 结合，形成权限与审批的双重约束。

## 与组件 / 协议关系

- **与 [Casbin](/components/casbin) 的关系**：属于“授权模型规范”与“默认轻量进程内授权裁决引擎”的关系，负责日常 `RBAC + ABAC` 与工具动作授权裁决。
- **与 [OpenFGA](/components/openfga) 的关系**：当知识库或文档权限涉及跨系统深层继承图谱（如文件夹、项目、群组与动态分享链接）时，可在 `RBAC + ABAC`（`Casbin`）基线之上条件叠加 `OpenFGA` 承接 `ReBAC` 关系授权与 RAG 文档级 ACL 预过滤，两者互补协作。
- **与 [身份接入协议（OIDC / OAuth2 / SAML / SCIM）](/protocols/identity-access) 的关系**：属于“身份来源”与“权限裁决”的协作关系，认证不能替代授权。
- **与 [OpenMetadata](/components/openmetadata)、[LlamaIndex](/components/llamaindex) 配合**：依托标签、数据域与访问范围承接知识层的属性约束。
- **与 [APISIX](/components/apisix) 配合**：网关负责前置校验与上下文传递，业务授权结果仍由统一裁决口径决定。

## 适用场景

- 应用目录与工作台访问控制
- 知识库、数据集与检索结果过滤
- 工具调用与敏感操作授权
- 多租户、跨部门与跨项目协作
- 临时授权、时段授权与环境隔离

## 边界

- 不替代身份认证、组织同步与会话管理。
- 不替代审批流、人工复核与高风险动作确认。
- 不等同于将所有条件写入角色；动态约束不应强行耦合进角色模型，避免角色数量失控膨胀。
- 不等同于仅使用 `ABAC`；缺少稳定角色模型会导致日常运营与权限审计失控。

## 落地规则

- **建立统一主体模型**：优先定义用户、组、角色、租户、部门、应用、数据域、工具与动作的统一建模口径。
- **动静职责分层**：常规入口权限落于 `RBAC`，上下文限制落于 `ABAC`，避免重复建模。
- **高风险四要素判定**：高风险动作须至少同时评估主体、动作、目标对象与环境上下文。
- **临时授权闭环管理**：临时授权与例外授权必须设定有效期、责任人与审计记录，防止演变为长期隐性权限。
- **策略版本化发布**：权限策略须纳入版本管理与发布流程，严禁散落在前端判断或服务私有代码中。

## 治理注意点

- **控制角色膨胀**：定期清理近义角色与无主角色，防止角色数量无限增长。
- **统一属性字典**：统一“部门”“项目”“数据等级”等属性字典与取值口径，避免跨系统语义漂移。
- **排查职责冲突**：定期检查互斥角色组合，防止同一主体既能发起又能批准高风险动作。
- **全量留痕复盘**：将授权结果、命中规则、临时授权状态与审批状态写入统一审计链路，支撑事后复盘。
