# 方案综述

::: info 核心摘要
**企业级智能体开源系统方案**面向企业真实生产环境，提供一套可长期运行、私有化可控、边界清晰的智能体平台建设方法。

- **体系化链路**：将模型、知识、工具、工作流与多 Agent 能力纳入统一受控链路，避免单点堆砌。
- **治理内建**：从架构初期即纳入身份权限、审计留痕、评测门槛、容量验证与发布回滚机制。
- **单轨收敛**：核心能力域收敛为单一主底座，兼顾开源优先、私有化部署与长期可演进性。
- **核心入口**：[方案总览](/framework) · [总体架构](/architecture) · [技术选型](/stack) · [安全与治理](/governance)
:::

## 方案解决的问题

企业级智能体平台建设关注的不是单点模型接入，而是围绕企业真实生产环境建立可长期运行的系统底座：

- **全链路受控集成**：将模型、知识、工具、工作流与多 Agent 能力纳入同一条受控链路。
- **治理能力前置内建**：在架构初期即将权限控制、审计留痕、离线评测、容量验证与发布门槛纳入设计。
- **平台底座沉淀复用**：将试点验证沉淀为可复用的平台底座，避免每个业务场景重复搭建独立系统。
- **开源可控与持续演进**：在开源优先的前提下，保障私有化部署、安全边界可控与技术栈持续演进能力。

## 方案边界

为明确交付与职责边界，本方案不直接覆盖以下范围：

- **非单一业务交付代码**：不直接等同于某一个具体业务应用的完整交付代码。
- **不强制单一主平台**：不假定所有企业采用同一条主平台路线，而是提供收敛后的二选一决策规则。
- **不包含外部系统私有细节**：不将各类外部业务系统的具体集成细节写入主架构方案。
- **区分演示验证与生产运行**：方案面向生产级治理与部署标准，而非轻量 Demo 搭建。

## 一句话架构总览

::: tip 核心技术主链
`APISIX` + 统一门户与 BFF（`AgentifUI` / `LibreChat` + 门户 / BFF / API 层）+ 一条主平台路线 + `LangGraph` + `LlamaIndex` + `LiteLLM` + `vLLM` + 数据治理链路 + 双层观测治理体系
:::

上述主链确立了六项核心架构分工：

- **北向入口收敛**：所有渠道请求经统一接入网关进入平台，完成认证接入、限流与审计前置。
- **第 3 层门户解耦**：以 `AgentifUI`（默认，面向 `Dify` / `LangGraph` 应用目录与工作流）或 `LibreChat`（并列参考，纯 `MIT`，面向通用多模型 / `MCP` 共享对话）+ 门户 / BFF / API 层承接企业全员共享统一入口与多应用分发；个人自治型超级智能体（如 `OpenClaw`）归入 [扩展升级](/extension-capabilities) 按独立沙箱多实例隔离评估，不纳入共享门户基线。
- **主平台单轨收敛**：标准场景主平台从两条候选路线（`Dify` / `RAGFlow`）中收敛为唯一主底座，避免长期并行。
- **复杂流程专职承接**：长链路状态机、人工确认与失败恢复由专门的 Agent Runtime 承接。
- **模型访问统一网关**：上层应用统一经模型网关调用推理服务，与底层模型实现解耦。
- **全周期治理内建**：数据治理、安全控制、双层可观测性（Observability）与发布验证贯穿全链路，而非事后补丁。

## 核心原则

### 1. 平台化优先于项目化

避免为每个业务场景单独搭建一套 Agent 系统，应优先沉淀模型网关、知识检索、工具接入、权限与审计、统一观测等共性能力。

### 2. 编排层与模型层解耦

模型能力与业务流程均处于快速演进中，两者必须通过统一接口解耦，避免因更换模型或推理后端而重写上层业务流程。

### 3. 治理内建而非后补

权限控制、敏感脱敏、高风险动作审批、人工接管、发布评测与容量验证均属于架构基线，不应推迟至试点成功后再补齐。

### 4. 单轨收敛原则

核心技术路线保持单轨收敛，同一能力域只保留一套主底座，避免长期并行多套同类平台或将互斥备选同时作为生产默认方案。

## 适合优先落地的场景

| 场景 | 适合原因 | 主要能力要求 |
| --- | --- | --- |
| 内部知识助手 | 价值明确、数据边界较清晰、便于试点 | 知识接入、权限过滤、引用留痕 |
| 服务台智能分诊 | 可直接体现效率收益 | 工具调用、审计、人工确认 |
| 流程自动化 Agent | 能体现平台化价值 | 状态机、回放、审批、补偿 |
| 数据分析助手 | 价值高，但治理要求更高 | 查询安全、指标口径、人工验真 |

## 交付边界

本方案默认交付三类成果：

1. **文档体系**：面向管理层、架构师和实施团队的统一架构与规范说明。
2. **平台蓝图**：明确开源组件选型、模块边界、治理要求和部署拓扑。
3. **实施路线**：覆盖 PoC、部门试点到企业级生产推广的阶段目标与验收口径。

本方案不直接替代以下专项工作：

- 具体业务系统改造项目
- 企业内部主数据治理项目
- 各业务部门自定义流程和表单建设工作
